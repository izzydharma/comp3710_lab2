# COMP3710 Lab 2 — Pattern recognition and deep learning

Coursework repository maintained by **izzydharma**. It contains the Fourier/PCA/LFW experiments and independently runnable PyTorch implementations of CIFAR-10 ResNet-18, MRI reconstruction, segmentation and generation. Models are trained from scratch; no pretrained weights are used.

## Project map

| Part | Entry point | Method / output |
|---|---|---|
| 1 | `lab2.ipynb` | Square-wave Fourier series, direct DFT, FFT and GPU timing |
| 2 | `lab2.ipynb` | PCA eigenfaces and Random Forest identity classification |
| 3.1 | `lab2.ipynb` | Two 3×3, 32-filter convolution layers for LFW classification |
| 3.2 | `part3.py` | CIFAR-adapted ResNet-18 classification |
| 4 Task 1 | `task1_vae.py` | VAE reconstruction and latent-space visualisation |
| 4 Task 2 | `task2_unet.py` | U-Net categorical MRI segmentation |
| 4 Task 3 | `task3_gan.py` | WGAN-GP MRI generation |

Each Part 4 task intentionally stays in **one standalone Python file**, including its data helpers. No local helper module is needed. Shared conventions are documented in [Design and workflows](docs/DESIGN.md).

## Setup

Use a separate Python environment (the recorded Rangpur ResNet run used Python 3.11). Install a compatible **PyTorch/torchvision pair** for the machine using the [official installation selector](https://pytorch.org/get-started/locally/), then install the remaining packages:

```bash
python -m pip install -r requirements.txt
python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available())"
```

`requirements.txt` lists direct dependencies; it is not an exact environment lock. Saved run configurations record experiment settings and, where available, runtime information. Matching a seed alone does not guarantee identical results across hardware and library versions.

For Parts 1–3.1, run `jupyter notebook lab2.ipynb` and execute cells in order from a fresh kernel. The first LFW/CIFAR download requires network access. Check printed image ranges before adding any extra normalisation.

## MRI dataset

Obtain the course-provided PNG dataset separately. Extract it next to the scripts; the loader accepts the common nested `keras_png_slices_data/keras_png_slices_data/` layout. Alternatively pass `--data-dir PATH` to any Part 4 task.

The dataset root must contain `keras_png_slices_train`, `keras_png_slices_validate`, and `keras_png_slices_test`, with the supplied paired mask folders for segmentation. Preserve filenames and the supplied subject splits. Do not randomly split adjacent slices from the same subject into training and test sets. The loader checks case overlap and mask/image pairing.

Datasets and model weights are excluded from new Git commits. The repository retains selected experiment outputs; checkpoint files must be obtained from the corresponding local/Rangpur run or regenerated by training.

## Run locally

Run these commands from the repository directory. Calling a script without arguments also starts its default training configuration, so an editor's Run button works.

```bash
python part3.py cifar10 --device cuda
python task1_vae.py --device cuda
python task2_unet.py --device cuda
python task3_gan.py --device cuda
```

Use `--device cpu` when needed; full training can be slow. Part 3.2 explicitly defaults to CUDA, while the MRI tasks automatically select a device by default. Inspect options with `python task2_unet.py --help` (similarly for the other scripts). `--output` must name a new/empty directory.

To evaluate saved MRI weights, replace the placeholder with a real checkpoint:

```bash
python task1_vae.py --mode evaluate --checkpoint PATH_TO_VAE_BEST_PT
python task2_unet.py --mode evaluate --checkpoint PATH_TO_UNET_BEST_PT
python task3_gan.py --mode evaluate --checkpoint PATH_TO_WGAN_LAST_PT
python part3.py demo --checkpoint PATH_TO_RESNET_BEST_PT --device cuda
```

The ResNet `demo` command evaluates and demonstrates an additional training epoch; it is not just a static prediction command. GAN evaluation generates samples and diagnostics. Its current WGAN-GP code requires a compatible WGAN-GP checkpoint, not an old BCE-GAN checkpoint. Checkpoints are model/configuration records, not complete optimiser-state training resumes.

## Rangpur

Upload the source scripts, job scripts and dataset, connect to Rangpur, then submit from the project folder:

```bash
sbatch run_part3.sh
sbatch run_task1_vae.sh
sbatch run_task2_unet.sh
sbatch run_task3_gan.sh
squeue --me
```

`sbatch` runs on the cluster, not Windows Command Prompt. The supplied job files assume the `comp3710` account/partition and a conda environment called `torch`. Check those settings against your allocation. Jobs request a GPU and execute on an allocated node; a pending job has not started training. The scripts use the partition memory default because of the reported Rangpur memory configuration. Inspect each job's `.out` and `.err` logs for errors.

## Results and validation

See [Results with evidence](docs/RESULTS.md) for the selected run folders, metrics, figures and limitations. Raw outputs remain available under `part3_results/` and `part4_results/`; older runs are historical comparisons, not current scores.

Run the small CPU checks without downloading datasets:

```bash
python -m unittest discover -s tests -v
```

These checks cover model shapes, finite training gradients, known Dice behaviour and the WGAN input-gradient penalty. They do not replace full training, dataset validation or the assessed Rangpur demonstration.
